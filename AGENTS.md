# Инструкция для ИИ-агентов: как работать с этим проектом

Этот файл — правила для **любого ИИ-агента** (Claude Code, Codex, Cursor, Cline,
Windsurf, Aider и др.), который работает в корневом репозитории Reasonable Engine.
Прочитай его целиком до внесения первых правок.

> ⚠️ Не путай: это инструкция для агентов, работающих **с исходным кодом движка**.
> Файлы `AGENT_GUIDE.md` / `AGENTS.md` внутри папок пользовательских проектов —
> это генерируемые пакеты для агентов, работающих **над играми пользователей**. Их
> содержимое строится кодом в `reasonable/ai/external.py` и `templates/*`.

---

## 1. Карта репозитория

| Путь | Что это | Можно менять? |
|---|---|---|
| `reasonable/core/` | Ядро: `i18n.py`, `settings.py`, `paths.py`, `project.py`, `scaffold.py`, `history.py`, `progress.py`, `convert.py`, `chatlog.py`, `usage.py` | Да, по задаче |
| `reasonable/editor/` | Редактор на PySide6 (весь UI пользователя) | Да, по задаче |
| `reasonable/ai/` | Встроенный агент: `agent.py`, `tools.py`, `client.py`, `providers.py`, `drawing.py`, `sprites.py`, `external.py`, `prompts_en.py` | Да, по задаче |
| `reasonable/runtime/` | pygame-рантайм; **вендорится в проекты пользователей** (`_engine/reasonable`) | Осторожно: обратная совместимость |
| `reasonable/templates/` | Шаблоны проектов (`game`, `app`, `blank`, `simple`) | Осторожно: их читают тесты и scaffold |
| `tests/` | Автотесты (`unittest`) | Новые тесты — да; существующие якоря — см. §5 |
| `docs/` | Внутренняя документация (архитектура, CLI, Android, тестирование) | Да, синхронно с кодом |
| `tools/`, `installer/`, `*.spec`, `build_*.bat` | Сборка `.exe`, установщика, портативного Python | Только по задаче сборки |
| `Reasonable Engine Public/` | **Публичный репозиторий пользователя**: README, CHANGELOG, CONTRIBUTING, LICENSE, docs — без исходного кода | Только через §3 |
| `README.md` (корень) | Главный внутренний readme | Да, синхронно с кодом |
| `I18N-HANDOFF.md` | Бриф незавершённой работы по двуязычности RU/EN | Читать, не переписывать |
| `reasonable/version.py` | `VERSION`, `VERSION_LABEL` (RE-2.01 и т.д.) | Только при выпуске релиза (§4) |

Запрещено менять без явного запроса пользователя: `LICENSE*`, `installer/EULA.txt`,
бренд-ассеты (`logo.png`, `reasonable/assets/brand`), заставку (`runtime/splash.py` —
она часть движка и не отключается).

## 2. Обязательный цикл любой правки

1. **Понять контекст.** Прочитать соответствующий модуль и связанные тесты ДО правки.
   Не предполагай состояние файлов — открывай их.
2. **Минимальное изменение.** Не переписывай сделанное; доделывай перечисленное.
   Один патч — одна логическая задача.
3. **Компиляция.** После каждого изменённого `.py`: `python -m py_compile <файл>`.
4. **Тесты.** Из корня: `python -m unittest discover -s tests -v`
   (или `python -m pytest tests -q`; для Qt-тестов нужен
   `QT_QPA_PLATFORM=offscreen`). Все тесты обязаны оставаться зелёными.
5. **Дифф.** `git diff --stat` — только ожидаемые файлы, ничего случайного
   (никаких `__pycache__`, логов, временных файлов).
6. **Отчёт.** Пользователю скажи: что изменено, почему, как проверено.

Сборку установщика не запускать (нужен Inno Setup) — проверяй синтаксис `.iss` вручную.
Параллельных субагентов не использовать — работай последовательно.

## 3. ПУБЛИЧНЫЕ ИЗМЕНЕНИЯ → «Reasonable Engine Public» (важнейшее правило)

Любое изменение, которое видят пользователи публичного репозитория, **обязательно**
фиксируется в папке `Reasonable Engine Public/` (в GitHub-терминологии это
github-public/changelog):

- новая функция, исправление, изменение поведения или UX;
- изменение версии/релиза;
- изменение публичных инструкций, лицензии, документации пользователя.

Что делать:

1. **Changelog — всегда в двух файлах и зеркально:**
   - `Reasonable Engine Public/CHANGELOG.ru.md` (русский — основной);
   - `Reasonable Engine Public/CHANGELOG.md` (английский — точный перевод тех же пунктов).
2. Добавляй пункт в раздел текущего **невыпущенного** релиза; если раздела ещё нет —
   создай его сверху по формату существующих: `## [RE-1.xx] — YYYY-MM-DD` с подразделами
   `### Добавлено / ### Исправлено / ### Изменено` (EN: `Added / Fixed / Changed`).
3. Стиль пункта: **жирное короткое имя** — затем одно-два предложения «что и зачем»,
   ориентированных на пользователя (без имён модулей и внутреннего жаргона).
   Пиши факт результата («Экспорт сохраняет на Рабочий стол»), а не процесс
   («поправил export_dialog.py»).
4. Если изменение меняет возможности продукта — обнови также `README.ru.md` /
   `README.md` публичной папки и при необходимости `docs/` (+ `docs/ru/`).
5. Пункты на русском и английском должны быть **парными**: добавил один — добавь второй.
6. Внутренний код и публичные записи коммитятся вместе, чтобы changelog не отставал.

Не пишутся в публичный changelog: рефакторинги без пользовательского эффекта,
изменения тестов, сборочные скрипты, внутренние заметки.

## 4. Система версий

Формат: **RE-<поколение>.<релиз>** (RE-2.01, RE-2.02…). Правила:

1. Первый релиз поколения — всегда `.01`; версии «RE-2.00» не существует.
2. Номера идут подряд: после RE-2.09 → RE-2.10, после RE-2.99 → RE-2.100.
3. Поколение меняется только при глобальном обновлении движка (новая архитектура,
   несовместимый формат проектов) и никогда не откатывается.
4. При выпуске релиза синхронно обнови: `reasonable/version.py` (`VERSION`,
   `VERSION_LABEL`), заголовок changelog'ов (раздел `[RE-x.xx]` получает дату),
   упоминания текущей версии в обоих README и в этом файле.

Текущий статус: **RE-2.01** — первый релиз поколения Reasonable Engine 2.

## 5. Двуязычность (i18n) — конвенции

Механика: `reasonable/core/i18n.py`, функция `t(key, **values)`; пары строк
создаются `_pair("русский", "english")`; язык: env `REASONABLE_LANG` → override →
`settings.json` (`ui.language`) → маркер установщика → `"ru"`.

Строгие правила (нарушение роняет тесты):

1. Русский текст в `_pair(...)` — **байт-в-байт** прежний литерал. Русские строки уже
   подобраны под якоря тестов (`tests/test_editor.py`, `tests/test_convert.py`) —
   не «улучшай» их.
2. Ключи ASCII: `<префикс>.<snake_case>`; префиксы заняты по модулям
   (`settings.`, `projectpage.`, `newproj.`, `projset.`, `chat.`, `workers.`,
   `widgets.`, `export.`/`exportdlg.`, `historydlg.`, `convdlg.`, `extpanel.`,
   `assets.`, `code.`, `aipanel.`, `cli.`, `branding.` и др.). Существующие ключи
   сначала искать в `TRANSLATIONS`; новый блок добавляй секцией с комментарием.
3. НЕ переводить: имена провайдеров/моделей, URL, пути, команды, бренд
   «Reasonable Engine», «Windows»/«Android», техтокены.
4. Материал для ИИ-агента движка (промпты, навыки, инструменты) — **только английский**
   (`ai/prompts_en.py`; кириллица в `ai/tools.py` допустима лишь внутри пар `_t("EN","RU")`).
5. Незавершённая работа по локализации описана в `I18N-HANDOFF.md` — продолжай по её
   списку, не переделывая выполненное.

## 6. Архитектурные ограничения

- **Редактор** — только PySide6/Windows. **Runtime** — только pygame + stdlib
  (без Qt!), работает на Windows и Android. Не тяни Qt в runtime и templates.
- Runtime вендорится в каждый проект: меняй его обратно совместимо, импорт тяжёлых
  зависимостей — внутри функций (см. приём `_load_logo` в `runtime/splash.py`).
- Прогресс — общий протокол встроенного и внешнего агентов: `progress/state.json` +
  `progress/events.jsonl` (`core/progress.py`). Процент выводится из задач плана
  автоматически; не выставляй нули вручную.
- История версий проекта: снимок создаётся автоматически перед каждым запуском
  агента (`core/history.py`); восстановление тоже отменяемо. Не удаляй снапшоты.
- Заставка движка обязательна и не может быть отключена пользователем или шаблоном.
- Конвертация проектов создаёт **новый** проект, не изменяя исходный.

## 7. Быстрые команды

```bash
# все тесты
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v
pytest tests -q

# проверка синтаксиса одного файла
python -m py_compile reasonable/<модуль>/<файл>.py

# редактор вручную (обычно нельзя — нет GUI; только offscreen-проверки)
REASONABLE_LANG=en python -m reasonable --version

# валидация пользовательского проекта
python -m reasonable.cli --project <папка> validate
```

## 8. Чего никогда не делать

- Не коммитить секреты, API-ключи, личные данные; не публиковать исходники движка
  в публичную папку (лицензия закрытая — см. `LICENSE.ru.txt`).
- Не отключать, не «оптимизировать» и не обходить заставку и фирменные элементы.
- Не менять существующие тестовые якоря под свой код — код подгоняется под тесты.
- Не писать в публичный changelog раньше, чем изменение есть в коде; и наоборот —
  не оставлять пользовательское изменение без записи в changelog (§3).
- Не трогать `templates/*` и содержимое project-файлов без явной задачи.
