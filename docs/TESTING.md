# Тестирование Reasonable Engine

Тесты используют стандартный `unittest` из Python. Дополнительные пакеты вроде `pytest` не нужны.

---

## Быстрый запуск

Из корня репозитория:

```bat
python -m unittest discover -s tests -v
```

Ожидаемый результат на версии 0.1.0: **64 теста, OK**.

Для читаемого вывода в Windows PowerShell:

```powershell
$env:PYTHONIOENCODING="utf-8"
python -m unittest discover -s tests -v
```

---

## Отдельные модули

```bat
python -m unittest tests.test_paths -v
python -m unittest tests.test_progress -v
python -m unittest tests.test_project -v
python -m unittest tests.test_settings -v
python -m unittest tests.test_agent_tools -v
python -m unittest tests.test_sprites -v
python -m unittest tests.test_scaffold -v
python -m unittest tests.test_export -v
python -m unittest tests.test_convert -v
python -m unittest tests.test_cli -v
python -m unittest tests.test_editor -v
```

Тесты редактора требуют offscreen-режим Qt:

```powershell
$env:QT_QPA_PLATFORM="offscreen"
python -m unittest tests.test_editor -v
```

В Linux/macOS:

```bash
QT_QPA_PLATFORM=offscreen python -m unittest tests.test_editor -v
```

`tests/test_editor.py` также выставляет `QT_QPA_PLATFORM=offscreen` самостоятельно, если переменная не задана, но явное указание надёжнее.

### Важные особенности

- **Тесты не вызывают реальные ИИ-API.** Проверяются инструменты, прогресс, scaffold и редактор, а не сетевые модели.
- **Тесты не собирают APK.** Проверяется содержимое Android ZIP и `buildozer.spec`, но buildozer требует Linux/WSL2.
- **Тесты конвертации не мутируют исходник.** Они проверяют новую папку, `CONVERSION.md`, `converted_from`, пересборку `_engine/` и сохранность исходного проекта.
- **Frozen self-test** (`dist\ReasonableEngine.exe --self-test`) проверяет уже упакованный `.exe`, а не исходники. В установленной версии он дополнительно проверяет `ReasonablePlayer.exe`, портативный Python и папку `Projects` внутри папки установки. Отчёт можно записать в файл через `REASONABLE_SELF_TEST_REPORT`.
- **Headless-запуск** использует `SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy`, `RE_SKIP_SPLASH=1` и `RE_FRAMES`.
- **Временные папки** создаются через `tempfile.TemporaryDirectory`, поэтому тесты не трогают ваши проекты и настройки.
- **Настройки редактора** в тестах направляются в временную папку через `REASONABLE_HOME` или `Settings(path=...)`.
- **PySide6 опционален для не-editor тестов.** `test_editor.py` пропускается, если PySide6 не установлен.

## Ручной чек-лист

Автотесты не заменяют визуальную проверку. Перед релизом пройдите сценарий.

### Установка и запуск

- [ ] `python -m pip install -r requirements.txt` проходит без ошибок.
- [ ] `python -m reasonable --version` печатает версию.
- [ ] `python run_editor.py` открывает редактор.
- [ ] Двойной клик по `Reasonable Engine.bat` работает.
- [ ] `Reasonable Engine (без консоли).vbs` не показывает консоль.
- [ ] Окно не меньше 1120×750, интерфейс не обрезается.

### Установщик на чистой машине

- [ ] `build_installer.bat` создаёт `dist\ReasonableEngine-Setup-0.1.0.exe`.
- [ ] Установщик показывает лицензию (`installer\EULA.txt`) и не требует прав администратора.
- [ ] После установки в `%LOCALAPPDATA%\Programs\Reasonable Engine` есть `ReasonableEngine.exe`, `ReasonablePlayer.exe`, `runtime\python\python.exe` и `Projects`.
- [ ] `ReasonableEngine.exe --self-test` в папке установки проходит все проверки.
- [ ] Кнопка **«Запустить»** открывает игру через `ReasonablePlayer.exe`, а не второй редактор.
- [ ] В проекте из `<установка>\Projects` команды `re.bat validate`, `re.bat --version` и `run.bat` работают без системного Python (проверьте с урезанным `PATH`).
- [ ] Новый проект по умолчанию создаётся в `<установка>\Projects`; папку можно сменить в настройках.

### Настройки

- [ ] Открываются по `Ctrl+,`.
- [ ] По умолчанию видны только основные настройки: ИИ-помощник, папка проектов, предпросмотр.
- [ ] Переключатель **«Расширенные настройки»** показывает провайдеров, модели, Base URL, картинки и агента; выбор запоминается.
- [ ] Список провайдеров читается, названия не обрезаны.
- [ ] «Загрузить модели» показывает статус и не вешает UI.
- [ ] «Проверить подключение» даёт понятный результат.
- [ ] Ключ скрыт, кнопка «Показать» работает.
- [ ] Сохранение и повторное открытие сохраняют провайдера, модель и ключ.
- [ ] Неверный ключ даёт ошибку, а не падение.

### Создание проекта

- [ ] Стартовый экран предлагает три действия: **Создать с ИИ**, **Открыть проект**, **Пустой проект**.
- [ ] Выбор провайдера не требуется до первого запуска агента.
- [ ] Мастер с ИИ: первый шаг — короткая цель, тип и режим агента.
- [ ] Переключение «игра/приложение» обновляет сводку.
- [ ] Переключение «встроенный/внешний» обновляет подсказку без ошибок.
- [ ] В мастере нет полей разрешения, ориентации, полноэкранного режима и большого промпта.
- [ ] Второй шаг принимает название и папку, создаёт проект и показывает прогресс.
- [ ] После создания сразу открывается раздел **«ИИ-агент»** с полем первой задачи.
- [ ] **Пустой проект** сразу открывает **«Код»**, создаёт минимальный `main.py` без игры и без вопросов про ИИ.
- [ ] В папке есть `main.py`, `project.json`, `assets/`, `progress/`, `_engine/`, `AGENT_GUIDE.md`, `re.bat`.
- [ ] В `project.json` есть `platform`, `notes`, `window.mode` и `window.resizable`.

### Проект и ручная работа

- [ ] Разделы называются **Обзор**, **ИИ-агент**, **Код**, **Ассеты**.
- [ ] В шапке видны тип, платформа (`WINDOWS`/`ANDROID`), режим агента и активная модель/провайдер.
- [ ] Боковая панель показывает платформу, разрешение, режим окна и ориентацию.
- [ ] «Обзор» показывает цель, заметки и прогресс.
- [ ] Вверху обзора видна карточка **«Результат запуска»** с успехом/ошибкой и текстом ошибки.
- [ ] «Запустить» открывает игру/приложение с заставкой.
- [ ] После ошибки доступны **«Запустить снова»**, **«Исправить с ИИ»** и **«Вернуть рабочую версию»**.
- [ ] Заставка пропускается после 0,85 с.
- [ ] Консоль показывает логи, «Остановить» завершает процесс.
- [ ] Код открывается, подсвечивается, сохраняется по `Ctrl+S`.
- [ ] Создание файла и папки работает.
- [ ] Изображение открывается в предпросмотре.
- [ ] Ассеты отображаются, генерация спрайта создаёт PNG в `assets/sprites/`.
- [ ] Настройки проекта сохраняют имя, цель, заметки, окно, ориентацию и Android-пакет.
- [ ] В настройках проекта окно и Android скрыты под переключателем **«Расширенные параметры»**.
- [ ] F11 в запущенном проекте переключает полный экран, `RE_FULLSCREEN=1` запускает сразу на весь экран.
- [ ] Разделы переключаются кликом и `Ctrl+1…Ctrl+4`, включая «Код», «Ассеты» и запущенный предпросмотр.

### История версий и откат

- [ ] Перед запуском встроенного агента появляется сообщение о снимке, в `.reasonable/history/` создаётся папка.
- [ ] Карточка **«История версий»** в обзоре и кнопка в боковой панели открывают диалог.
- [ ] `Ctrl+Shift+H` и **Проект → История версий…** работают.
- [ ] В списке видны время, причина, число изменённых файлов и результат запуска агента.
- [ ] Возврат версии сначала создаёт страховочный снимок; откат можно отменить повторным возвратом.
- [ ] После возврата открытые файлы и дерево кода обновляются, проект запускается.
- [ ] «Снимок сейчас» создаёт ручную версию.
- [ ] `.reasonable`, `_engine`, `.git`, кэши и сборки не попадают в снимок.

### Встроенный агент

- [ ] В проекте со встроенным режимом раздел «ИИ-агент» показывает чат и поле задачи.
- [ ] Без ключа показывается понятная подсказка.
- [ ] С ключом агент начинает работу, видны шаги и инструменты.
- [ ] План и процент обновляются; карточка «Текущий план» показывает статусы задач.
- [ ] После запуска видна карточка **«Что изменил агент»**: файлы, действия, результат, кнопки открытия файла, отмены и истории.
- [ ] «Отменить эти изменения» возвращает снимок, созданный перед запуском агента.
- [ ] Кнопка «Стоп» останавливает агента.
- [ ] Ошибка сети показывается в чате и не ломает редактор.
- [ ] После завершения проект запускается.

### Внешний агент

- [ ] В проекте с внешним режимом тот же раздел «ИИ-агент» показывает чек-лист пакета.
- [ ] Первая задача пишется после создания проекта и копируется в буфер.
- [ ] «Обновить пакет агента» не падает.
- [ ] «Скопировать» кладёт промпт в буфер.
- [ ] `re.bat event "тест"` появляется в ленте.
- [ ] `re.bat progress 25 "..."` двигает прогресс.
- [ ] `re.bat task t1 done` отмечает задачу.
- [ ] «Открыть папку» и «Открыть AGENT_GUIDE.md» работают.
- [ ] В режиме одного агента второй раздел агента не появляется.

### Конвертация

- [ ] **Проект → Конвертировать в новый проект…** и кнопка в боковой панели открывают диалог.
- [ ] Диалог предлагает платформу, отличную от текущей, имя и папку.

## Проверка ИИ вручную

Автотесты не обращаются к моделям. Для ручной проверки:

1. Настройте провайдера.
2. Нажмите «Загрузить модели».
3. Нажмите «Проверить подключение».
4. Создайте тестовый проект.
5. Дайте агенту небольшую задачу: «Добавь экран паузы с кнопками “Продолжить” и “В меню”».
6. Проверьте:
   - агент читает файлы перед правкой;
   - вызывает `edit_file`, а не перезаписывает всё без причины;
   - запускает `validate_project` и `run_project`;
   - обновляет план;
   - завершает работу через `finish`;
   - проект запускается после изменений.

Для слабых моделей:

- увеличьте `max_steps`;
- уменьшите `context_messages`;
- выберите модель с tool calling;
- дайте более узкую задачу.

## Диагностика тестов

| Симптом | Решение |
|---|---|
| `ModuleNotFoundError: PySide6` | `python -m pip install -r requirements.txt` |
| `qt.qpa.plugin: could not find...` | Задайте `QT_QPA_PLATFORM=offscreen` |
| Тесты висят на editor | Проверьте, что не открыт модальный диалог; запустите модуль отдельно |
| `UnicodeEncodeError` | `PYTHONIOENCODING=utf-8`, `chcp 65001` |
| pygame пишет `pkg_resources is deprecated` | Предупреждение библиотеки, не ошибка |
| `Address already in use` | Остановите другой экземпляр редактора/теста |
| Тесты падают на путях | Не запускайте из папки с не-ASCII путями без UTF-8; проверьте `PYTHONPATH` |
| Долгий `test_scaffold` | Он создаёт проекты и запускает pygame headless; это нормально |
| APK-тест не проходит | Автотесты не собирают APK; проверяйте только ZIP |
| `Все выбранные параметры совпадают` | Для конвертации нужно хотя бы одно отличие: платформа, имя, ориентация, окно, агент или сброс прогресса |
| Диалог конвертации не открывается | Откройте проект, а не стартовый экран; проверьте, что PySide6 установлен |
| Frozen `.exe` не находит шаблоны | Пересоберите через `tools/build_editor_exe.py`; проверьте `engine_source/` и `reasonable/templates` в spec |

### Полная очистка кеша Python

## Добавление тестов

1. Создайте `tests/test_<область>.py`.
2. Используйте `unittest.TestCase`.
3. Для временных файлов — `tempfile.TemporaryDirectory`.
4. Для проектов — `Project.create(..., scaffold=False)` или полный scaffold, если нужен runtime.
5. Для editor — `QT_QPA_PLATFORM=offscreen` и `QApplication.instance() or QApplication(sys.argv)`.
6. Не вызывайте реальные API и не требуйте Android SDK.
7. Проверяйте коды возврата и содержимое файлов, а не только отсутствие исключений.

Шаблон:

```python
import tempfile
import unittest
from pathlib import Path

from reasonable.core.project import Project, default_manifest


class MyFeatureTests(unittest.TestCase):
    def setUp(self) -> None:
        self._tmp = tempfile.TemporaryDirectory()
        self.root = Path(self._tmp.name) / "project"
        self.project = Project.create(
            self.root,
            default_manifest("Тест", project_type="game", goal="Проверка"),
            scaffold=False,
        )

    def tearDown(self) -> None:
        self._tmp.cleanup()

    def test_feature(self) -> None:
        self.assertTrue(self.project.root.is_dir())


if __name__ == "__main__":
    unittest.main()
```
