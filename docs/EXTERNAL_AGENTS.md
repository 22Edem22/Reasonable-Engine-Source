# Внешние ИИ-агенты

Reasonable Engine умеет работать с двумя типами агентов:

- **встроенный агент** — живёт внутри редактора и сам вызывает инструменты;
- **внешний агент** — Claude Code, Codex CLI, Cursor, Cline, Windsurf, Aider или любой другой инструмент, который умеет редактировать файлы в папке проекта.

Внешний режим не требует API-ключа в настройках редактора. Редактор **не запускает** внешний агент и не управляет им: он готовит полный пакет инструкций, а затем читает общий файл прогресса и показывает работу в реальном времени.

---

## Как это работает

```text
Reasonable Engine                         Внешний агент
┌───────────────────────┐                ┌──────────────────────┐
│ создаёт пакет правил  │                │ читает AGENT_GUIDE.md│
│ и файлы progress/     │                │ и skills/            │
│                       │                │                      │
│ каждые ~1,6 сек       │  progress/     │ меняет main.py,      │
│ читает state.json  ◄──┼── state.json ──┼─ assets/ и другие    │
│ и events.jsonl        │  events.jsonl  │ файлы проекта        │
│                       │                │                      │
│ показывает прогресс   │                │ вызывает re.bat      │
└───────────────────────┘                └──────────────────────┘
```

Ключевая идея — **папка проекта является общим интерфейсом**. Нет базы данных, сокетов и скрытого состояния: только файлы, которые можно прочитать, проверить и сохранить в резервную копию.

---

## Что создаётся в проекте

Пакет агента генерируется для **каждого** проекта, независимо от выбранного режима. Режим `external` подчёркивает, что проект будет вести внешний агент, и редактор открывает в разделе **«ИИ-агент»** именно панель внешнего агента. Режим задаётся при создании проекта; сменить его у существующего проекта можно через **«Конвертировать…»** — будет создана новая папка с пересобранным пакетом.

| Файл или папка | Назначение |
|---|---|
| `AGENT_GUIDE.md` | Полная инструкция: платформа проекта, архитектура, API движка, правила, чек-листы, команды. Для конвертированного проекта содержит источник и историю конвертации |
| `EXTERNAL_AGENT.md` | Как подключить Claude Code, Codex, Cursor, Cline, Windsurf и другие инструменты |
| `AGENTS.md` | Короткая памятка для агентов, читающих `AGENTS.md` |
| `CLAUDE.md` | Точка входа для Claude Code |
| `.cursor/rules/reasonable-engine.mdc` | Правило Cursor с `alwaysApply: true` |
| `.github/copilot-instructions.md` | Инструкции для GitHub Copilot |
| `skills/*.md` | Навыки: базовые для всех проектов + по типу проекта и уровням интерфейса |
| `AGENT_TASKS.md` | Стартовый план работ. Создаётся один раз и не перезаписывается командой `pack` |
| `.reasonable/agent_pack.json` | Версия пакета, версия движка и режим проекта |
| `re.bat` / `re.sh` | CLI проекта: прогресс, проверка, ассеты, экспорт |
| `progress/state.json` | Текущий снимок прогресса |
| `progress/events.jsonl` | История событий |
| `_engine/reasonable/` | Встроенная копия runtime |

### Навыки

Базовый набор (есть во всех проектах):

- `engine-basics.md` — как устроен runtime и какие модули использовать.
- `sprites-and-assets.md` — генерация спрайтов, фонов, иконок и правила именования.
- `progress-and-handoff.md` — как обновлять план и передавать работу.
- `android-and-export.md` — ограничения Android, касания, ориентация, сборка.

Дополнительные — по типу проекта и выбранным уровням интерфейса:

- `game-development.md` — для игр: игровой цикл, сцены, ввод, столкновения, баланс.
- `app-development.md` — для приложений: экраны, формы, списки, навигация, аккуратный UI.
- `ui-simple-tkinter.md` — уровень «Простой»: оконные tkinter-программы.
- `ui-standard-widgets.md` — уровень «Стандартный»: готовые виджеты движка.
- `ui-advanced-scenes.md` — уровень «Продвинутый»: сцены, камера, частицы, кастомная графика.

В проект попадают только навыки, соответствующие его уровням интерфейса: у
простой tkinter-утилиты не будет навыков игровых сцен, а у игры — tkinter.
Изменить состав можно через **«Конвертировать…»**.

## Быстрый старт

### 1. Создайте проект

В мастере нового проекта на первом шаге выберите **«Внешний агент»**. Это влияет на стартовые тексты, статус и содержимое раздела **«ИИ-агент»**, но все файлы пакета создаются в любом случае.

После создания сразу откроется раздел **«ИИ-агент»** с полем первой задачи. Опишите её там — текст можно скопировать в Claude Code, Codex, Cursor или другой инструмент. Первая задача намеренно пишется после создания проекта, когда видно стартовый экран и структуру.

Если проект уже существует, откройте его в редакторе: в режиме `external` раздел **«ИИ-агент»** показывает панель внешнего агента. Проект, созданный во встроенном режиме, тоже содержит пакет; чтобы получить отдельную копию с внешним режимом, используйте **«Конвертировать…»**.

### 2. Откройте папку проекта в агенте

Выберите любой удобный инструмент:

#### Claude Code

1. Откройте терминал в папке проекта.
2. Запустите `claude`.
3. Claude Code автоматически прочитает `CLAUDE.md`, затем попросите его прочитать `AGENT_GUIDE.md`.

#### Codex CLI

1. Откройте терминал в папке проекта.
2. Запустите `codex`.
3. Убедитесь, что агент прочитал `AGENTS.md` и `AGENT_GUIDE.md`.

#### Cursor

1. **File → Open Folder** → папка проекта.
2. Правило `.cursor/rules/reasonable-engine.mdc` применяется автоматически.
3. В чате попросите: «Прочитай `AGENT_GUIDE.md` целиком и работай по нему».

#### Cline / Windsurf

1. Откройте папку проекта в VS Code или Windsurf.
2. Откройте чат агента.
3. Вставьте промпт ниже. Убедитесь, что агенту разрешено редактировать файлы и выполнять команды.

#### Aider

1. Запустите `aider` в папке проекта.
2. Добавьте в контекст `AGENT_GUIDE.md`, `project.json`, `main.py` и `progress/state.json`.
3. Работайте по тому же промпту.

### 3. Вставьте промпт

В разделе **«ИИ-агент»** (режим «Внешний агент») есть два поля:

- **«Ваша задача»** — что именно нужно сделать, обычными словами;
- **«Полный промпт»** — только для чтения: путь к проекту, обязательный рабочий
  цикл и ваша задача. Именно этот текст получает агент.

Кнопки **«Скопировать промпт»** и **«Скопировать только задачу»** копируют
соответствующий текст. Предпросмотр обновляется сразу при вводе задачи.

Шаблон полного промпта (в редакторе уже готов — скопируйте кнопкой):

> Ты работаешь над проектом «…» в папке: …
>
> 1. Прочитай `AGENT_GUIDE.md`, `skills/` и `progress/state.json` — там полные правила и API движка.
> 2. Работай автономно: меняй файлы, генерируй ассеты, проверяй запуск (`re.bat validate`, `re.bat run --headless`).
> 3. Обновляй план и прогресс через `re.bat` (plan/task/progress/event) — пользователь видит его в Reasonable Engine.
> 4. Заверши через `re.bat done "итог"` только когда проект запускается и задача выполнена.
>
> Не трогай папку `_engine` — это встроенная копия движка. Шаги не ограничены:
> работай до результата, не повторяй одно и то же действие.

### 4. Следите за работой в редакторе

Раздел **«ИИ-агент»** обновляется автоматически:

- статус: ожидание, работает, завершено, ошибка;
- процент и текущий этап;
- план и отметки задач;
- лента событий;
- недавно изменённые файлы;
- последняя активность.

Доступны кнопки **«Открыть папку»**, **«Обновить пакет агента»** и **«Открыть AGENT_GUIDE.md»**.

> Панель показывает прогресс только в том случае, если агент действительно вызывает `re.bat`. Если агент меняет файлы молча, редактор увидит изменения файлов, но не узнает этап и процент.

## Протокол прогресса

### Команды

```bat
re.bat status
re.bat plan "Собрать меню" "Добавить уровни" "Проверить сборку"
re.bat task t2 in_progress
re.bat progress 45 "Готов экран меню" --stage "Меню"
re.bat event "Добавлены враги"
re.bat validate
re.bat run --headless
re.bat done "Проект готов"
```

Статусы задач: `pending`, `in_progress`, `done`, `skipped`. Вместо `t2` можно указать номер задачи или часть её названия.

### `progress/state.json`

```json
{
  "version": 1,
  "mode": "external",
  "status": "running",
  "percent": 45.0,
  "stage": "Меню",
  "message": "Готов экран меню",
  "tasks": [
    {"id": "t1", "title": "Собрать меню", "status": "done"},
    {"id": "t2", "title": "Добавить уровни", "status": "in_progress"}
  ],
  "started_at": "2026-10-27T12:00:00+03:00",
  "updated_at": "2026-10-27T12:30:00+03:00",
  "last_event_at": "2026-10-27T12:30:00+03:00",
  "last_event": "Добавлены враги"
}
```

### `progress/events.jsonl`

Одна строка — одно событие:

```json
{"ts":"2026-10-27T12:30:00+03:00","type":"progress","message":"Готов экран меню","data":{"percent":45.0,"stage":"Меню","status":"running"}}
```

Файл дополняется, а при превышении примерно 2 МБ автоматически обрезается до последних строк. Редактор читает последние события и не требует перезапуска.

## Правила для внешнего агента

`AGENT_GUIDE.md` задаёт следующие ограничения и ожидания:

1. **Читать перед изменением.** Сначала guide, `project.json`, `progress/state.json`, затем код.
2. **Не менять `_engine/`.** Это копия runtime. Для обновления используется `re.bat sync-engine`.
3. **Работать в папке проекта.** Внешний агент технически не ограничен песочницей — ответственность на пользователе.
4. **Писать рабочий код.** Не оставлять заглушки и `TODO` вместо основных экранов.
5. **Генерировать ассеты в `assets/`.** Спрайты — `assets/sprites/`, фоны — `assets/backgrounds/`, звук — `assets/audio/`.
6. **Обновлять прогресс.** План, задачи и события должны появляться в редакторе.
7. **Проверять результат.** `re.bat validate`, затем `re.bat run --headless`.
8. **Завершать явно.** `re.bat done "итог"` только после успешной проверки.

## Платформа и конвертация

`AGENT_GUIDE.md` явно называет платформу проекта, ориентацию, окно и — для конвертированных копий — источник (`converted_from`).

- **Android-проект:** проверяйте касания, узкие экраны, safe margins, ориентацию и производительность. Не полагайтесь на мышь и правую кнопку.
- **Windows-проект:** проверяйте окно, горячие клавиши, изменение размера и запуск без консоли.
- **Конвертированный проект:** сначала прочитайте `CONVERSION.md`. Код и ассеты скопированы как есть; компоновка и управление под новую платформу автоматически не переписываются.
- **Смена платформы или режима агента** выполняется через `re.bat convert --to …` или **«Конвертировать…»** в редакторе. Исходный проект не меняется, поэтому правки продолжайте в новой папке.

Если внешний агент работает в конвертированной копии, попросите его начать с `AGENT_GUIDE.md` и `CONVERSION.md`, затем проверить `re.bat validate` и `re.bat run --headless`.

## Передача работы и продолжение

Внешний агент может быть остановлен в любой момент. Состояние проекта полностью лежит в файлах.

Продолжение работы:

1. Откройте проект в редакторе.
2. Посмотрите `progress/state.json` и раздел **«ИИ-агент»**.
3. Откройте папку в агенте.
4. Напишите: «Продолжи с текущего места. Прочитай `progress/state.json`, `AGENT_TASKS.md` и `AGENT_GUIDE.md`. Не переделывай готовое без причины».

Полезные команды:

```bat
re.bat status
re.bat events --limit 30
re.bat pack
re.bat sync-engine
```

- `pack` перегенерирует `AGENT_GUIDE.md`, `EXTERNAL_AGENT.md`, `AGENTS.md`, `CLAUDE.md`, правила и `skills/`. Существующий `AGENT_TASKS.md` сохраняется.
- `sync-engine` обновляет `_engine/` после обновления Reasonable Engine. Перед этим закройте запущенный проект.

## Обновление пакета

Если вы обновили Reasonable Engine или хотите вернуть стандартные инструкции:

- в редакторе: раздел **«ИИ-агент» → «Обновить пакет агента»**;
- в проекте: `re.bat pack`;
- из корня движка: `python -m reasonable.cli --project "<папка>" pack`.

Команда не трогает ваш код и `AGENT_TASKS.md`. Она перезаписывает только файлы инструкций и навыков. После смены платформы через конвертацию пакет уже пересобран в новой папке; повторный `pack` нужен только после обновления самого Reasonable Engine.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Панель всё время «Ожидание» | Агент не вызывает `re.bat`. Попросите его выполнить `re.bat progress 10 "старт"`. |
| `re.bat` не найден | Команда выполняется не в папке проекта. Проверьте `cd`. |
| `python` не найден | Python не в `PATH`. Установите Python 3.10+ и перезапустите терминал. |
| Кракозябры в консоли | `re.bat` уже включает `chcp 65001`. Для сторонних оболочек задайте `PYTHONIOENCODING=utf-8`. |
| Агент игнорирует правила | Укажите файл явно: «Прочитай `AGENT_GUIDE.md` целиком перед первой правкой». |
| Файлы изменились, прогресса нет | Попросите агента обновить план и задачи через `re.bat`. |
| Устаревший движок | `re.bat sync-engine`, затем `re.bat validate`. |
| Ошибка `No module named reasonable` | Используйте `re.bat`, он добавляет `_engine` в `PYTHONPATH`. |
| Агент сломал запуск | `re.bat validate`, `re.bat run --headless`, откат по резервной копии или истории Git. |
| Агент не знает про Android | Попросите прочитать `AGENT_GUIDE.md`; проверьте `platform` и `orientation` в `project.json`. |
| Работа идёт не в той копии | Конвертация создаёт новую папку. Сверьте путь в `CONVERSION.md` и `progress/state.json`. |

### Проверка без агента

Убедитесь, что протокол работает:

```bat
re.bat event "тест связи"
re.bat progress 15 "Проверка" --stage "Тест"
re.bat status
```

Через 1–2 секунды панель в редакторе должна обновиться. Если нет — проверьте, что редактор смотрит на ту же папку проекта.

## Безопасность

- Внешний агент — это обычный процесс с правами вашего пользователя. Он **не** ограничен папкой проекта технически.
- Не давайте незнакомому агенту доступ к домашней папке, SSH-ключам и браузерным профилям.
- Работайте в Git или делайте резервные копии перед крупными изменениями.
- Пакет инструкций не содержит API-ключей. Ключи внешнего инструмента хранятся в его собственной конфигурации.
- Проверяйте команды, которые агент предлагает выполнить, особенно удаление файлов, установку пакетов и сетевые запросы.
